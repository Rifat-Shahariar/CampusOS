CAMPUSOS — PROJECT PLAN
=======================

PROJECT
-------
Name: CampusOS
Purpose: Smart Digital Campus Hub

Hackathon:
CPCCU AI-Powered Web App Development & Deployment Hackathon 2026

MVP MODULES
-----------
1. Club & Event Engine
2. Resource Hub

The application must provide a real, functional end-to-end
experience for both modules.

ACCOUNT & ROLE SYSTEM
---------------------

1. ADMIN
- Full platform access
- Manage users
- Manage clubs
- Manage club admins
- Manage resource admins
- Manage events
- Manage resources
- Manage system settings
- View platform-wide data
- Create/manage official notices

2. CLUB_ADMIN
- Can manage one or multiple assigned clubs
- Manage assigned club profiles
- Create/edit/delete events for assigned clubs
- Manage event registrations
- Manage QR check-in
- View attendance
- Create/edit/delete club posts and announcements
- Cannot manage unassigned clubs
- Cannot manage resources unless separately authorized

3. RESOURCE_ADMIN
- Can manage resources for ANY course
- Upload resources
- Edit resources
- Delete resources
- Organize resources by course/category
- Must specify batch and section when appropriate
- Cannot manage events or clubs

4. STUDENT
- Register/login
- Browse clubs
- Browse events
- Search/filter events
- Register for events
- View QR ticket
- View registration history
- Browse resources
- Search/filter resources
- Download resources

IMPORTANT RESOURCE RULE
-----------------------

Resource Admins do NOT require course assignment.

Any RESOURCE_ADMIN may manage resources belonging to any course.

Batch and section are stored as simple fields on the resource.

Example:

Course: CSE 2115
Batch: 67
Section: A
Type: NOTE

AUTHORIZATION RULES
-------------------

ADMIN:
- Full access

CLUB_ADMIN:
- Only assigned clubs
- Events/posts/attendance for assigned clubs

RESOURCE_ADMIN:
- All resource operations
- All courses
- No event/club administration

STUDENT:
- Read public content
- Register for events
- View own registrations/tickets
- Download resources


SECURITY
--------

- Passwords must be securely hashed.
- JWT authentication for protected APIs.
- RBAC enforced on backend.
- Club ownership/assignment must be verified server-side.
- Frontend restrictions are NOT the security boundary.
- Validate all request bodies using DTOs/Zod where appropriate.
- Validate file type and file size before upload.
- Never expose private credentials.
- Never commit .env files.


RESPONSIVE DESIGN
-----------------

The entire application must be optimized for:

- Mobile phones
- Tablets
- Laptops
- Desktop PCs
- Large displays

Use responsive/mobile-first design.

Avoid:
- horizontal overflow
- fixed-width layouts
- unusable tables on mobile
- tiny touch targets
- desktop-only navigation

Admin dashboards must also remain usable on mobile.

DEVELOPMENT PRINCIPLE
---------------------

Build incrementally.

Do not implement the entire project in one AI-agent prompt.

After every major step:
1. Run lint
2. Run tests where applicable
3. Run build
4. Fix errors
5. Verify functionality
6. Commit changes

Do not add features that are not in this plan without explicit approval.

AI features are NOT part of the initial MVP.
They may be added only after the core product is functional.
